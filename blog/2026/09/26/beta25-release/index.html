SkyrimNet Beta25 Released

September 26, 2026 · 27 min read

🎉 SkyrimNet Beta 25 Latest

Beta25 is our largest release yet. It brings quest progression and scripted dialogue actions into SkyrimNet conversations, launches the Plugin Hub and Content Library, and introduces a new routing system built to keep conversations moving when AI providers slow down or fail.

This release also launches Fateless, a home for community plugins and public model and provider statistics. Alongside those additions are major improvements to speech playback, voice input, memory context, customization, and support for Skyrim 1.7.104.

Before You Update​

Existing saves are supported. You do not need to start a new game. There are, however, important changes to plugins and custom content:

  • Update your SkyrimNet plugins. Plugins built for Beta24 and earlier need to be converted to Beta25's new Content Library format. Compatible plugins are published on the Plugin Hub, accessible from the dashboard's Plugins page. Old-format plugins will not work as-is.
  • Install powerofthree's Tweaks se/ae vr and leave its Load EditorIDs fix enabled. This is the default. SkyrimNet now uses it instead of Native EditorID Fix and no longer ships the Native EditorID Fix INI override.
  • Import older custom edits. Files in the old prompts/, config/triggers/, and config/actions/ folders are left untouched but are no longer read. Use Plugins → Installed Plugins → Import Old Content to bring over the content (Including save-specific bios for your current playthrough) you want to keep. The importer copies selected files rather than moving or deleting the originals and skips files identical to SkyrimNet's defaults. Its optional cleanup only removes files identical to stock. Some actions are renamed during import; the importer lists any enabled/disabled states or cooldowns you will need to reapply under Behavior → Actions.
  • Install the bio packs for your mods. SkyrimNet now bundles vanilla, DLC, and Creation Club bios only. Bio packs for other mods are distributed through the hub. Use View bio packs → Install all to install the packs matching your load order. Until then, NPCs from those mods will not have their written bios.

Existing virtual NPC definitions and settings newly supported by the Content Library migrate automatically on first launch. Their old files are retained, and any settings that could not migrate are identified in the relevant dashboard section. This automatic migration is separate from importing older prompt, trigger, and action edits.

Auto-Update Base Content is enabled by default. SkyrimNet can receive updates to its own prompts, triggers, and actions between releases. These apply at startup, never in the middle of a game. You can disable this under Settings → General or restore the content that shipped with your version.

Skyrim 1.7.104 Support (Min, Dowser)​

Skyrim 1.7.104 is supported with SKSE 2.3.1, the matching Address Library, and 1.7-compatible versions of powerofthree's Tweaks, PrismaUI, Papyrus Extender, PapyrusUtil, and MfgFix. Make sure those dependencies match your game version when upgrading. Support for 1.6.1170 and all other versions is unchanged.

Dialogue Actions & Quest Integration (Zevick)​

Quests and scripts normally triggered through the dialogue menu can now be used naturally through SkyrimNet-enabled speech. A new prompt exposes quest dialogue trees to the LLM and a new action allows for the execution of any dialogue script, or TIF. This system works with any script from any mod or vanilla.

Quests​

The new 0740_quest_dialogue prompt exposes any currently available quest dialogue to the speaking NPC with the help of the new available_dialogue(npc.UUID) decorator. This simulates the engine to display the dialogue options available for an NPC at that moment as if you were talking to them through the Skyrim dialogue menu. The LLM sees a full step-by-step dialogue tree and is instructed to follow it naturally in its own words, only when relevant to the conversation.

TriggerDialogueLine is the action that enables the LLM to move quests forward. When the conversation naturally reaches the decision point, the LLM will execute the dialogue script that starts a quest, progresses it, or rewards you. The wording of its instructions can be edited in dialogue_actions.prompt.

Note; this system cannot and makes no attempt to restructure any quests. They must still follow the same normal progression, just now in your own words.

More Actions​

This system extends beyond more than quests. Any dialogue script from any source can be now be executed through a single action. This includes things like renting a room, trading with a merchant, hiring a carriage, or anything added from a mod, such as refilling your waterskin or asking someone to ride on your horse.

You may find this to be too many options at first. In Settings > Dialogue Actions > Filters you can blacklist/whitelist plugins, quests, or TIFs from the system. NFF comes blacklisted by default because it dumps 20+ options for followers. There are also categories for vanilla scripts that can be toggled such as follower commands or merchant trading.

Additionally, you may find some scripts require more context for the LLM. In Settings > Dialogue Actions > Instructions you can create entries for specific TIFs that inject your guidance into the action prompt. To identify/obtain a TIF, you can use the Game Data Explorer's actor dialogue tab or search 'QUEST-TIF` in your SkyrimNet.log after it has been used in-game.

There are safeguards in place to ensure the scripts can only be used by the LLM when the game itself would allow the player to do so. More improvements to this system are planned, including quest discoverability and decision making.

Embedded Actions is recommended for this feature

Plugin Hub (Min, Zevick)​

The SkyrimNet Plugin Hub brings community content into one catalog, browsable both on Fateless and from the dashboard's Plugins page. No account or subscription is required to browse, install, or manage plugins.

The hub supports two kinds of entry. Bundles contain content SkyrimNet installs directly, such as prompts, bios, triggers, actions, and knowledge packs. You can preview and examine the contents of a bundle prior to installing through the dashboard. Listings point to mods hosted elsewhere, such as Nexus or GitHub, for integrations that also need their own ESP or DLL.

Find and Manage Content​

Every submission is reviewed before it is listed, and the catalog includes a curated selection. Signing in lets you endorse plugins or publish your own, but is not needed to use other people's content.

Published plugins also receive Discord discussion threads, with announcements when new versions are published, giving authors and users a place to discuss each plugin.

Bio packs for 215 mods are available out of the box, with bulk installation for matching packs.

Content Library and Shareable Settings (Min, Zevick)​

SkyrimNet's defaults, installed plugins, and your own edits now live separately. Updating SkyrimNet or a plugin no longer overwrites your custom version of a file.

The Content Library resolves files by priority: SkyrimNet's base content comes first, plugins override it in the order you choose, and your personal edits sit on top. When two plugins supply the same file, the higher-priority one wins. Conflicts are shown on Installed Plugins, where you can adjust the order. These conventions are similar to Mod Organizer (MO2)'s, and should feel familiar for modders that are used to managing Skyrim Mods through the tool.

Editors show which source supplies a file, let you Compare versions, and offer Revert to remove your edit and use the version beneath it. Customizing base or installed-plugin content through its dashboard editor saves your version to your personal overlay, leaving the original intact.

More Than Prompts​

Plugins can now include virtual NPCs, voice effects, item and spell names, furniture names, identity links, filters, and Dialogue Actions rules, alongside prompts, bios, triggers, actions, and knowledge packs.

These settings are stored as individual Content Library entries rather than one large configuration file per feature. Entries show which plugin provides them and have their own on/off switches, comparison tools, and options to add them to a plugin. Editing a supplied entry creates your own version; Revert to plugin restores the original.

Built-in filter and Dialogue Actions defaults are organized into named lists, such as Animals don't speak. Remove a list you do not want, restore it later, or create your own without replacing the entire configuration.

Plugins can also bundle their own Settings page definitions, so those pages install, update, and uninstall with the plugin. Changes to a plugin's settings page take effect without a restart.

Editors and Character Bios​

Tools → File Editor provides a single unified place to browse and manage the base content, installed plugins, your overlay, and the active save's files. This serves as a single convenient location for managing all types of content (prompts, triggers, knowledge entries, etc) across all of your installed content. It includes file comparison, pinning, conflict indicators, activation controls, and tools for copying content into your own plugins. Authoring details are covered below.

The Triggers and Actions pages group entries by the plugin that supplies them, with per-entry toggles, filters, and summary cards. Trigger search now includes event types, condition fields and values, and response text, not just names and descriptions.

Character bios have always had Static, Save-Specific, and Dynamic tabs. These are now exposed to you for easier and more visible control now through the updated UI. Regenerating a bio through sleep, a hotkey, or a script now preserves a backup that can be restored from the dashboard. Virtual NPCs can also be pinned on the Characters page once they exist in the current save.

Reloading configs from the dashboard also reloads Content Library edits without restarting. If a plugin installation is underway, the content reload waits until it finishes.

Persistent World Knowledge (Min)​

World knowledge can now be save-specific or persistent across playthroughs. Persistent packs live in the Content Library, load into each save, and synchronize again when their providing plugin updates. The World Knowledge page identifies them with Persistent and From plugin labels and lets you filter them separately from save-specific entries.

You can disable a supplied pack or individual entry for one save, and that choice survives plugin updates. Editing a supplied entry lets you choose between a save-specific copy and an overlay copy that applies across playthroughs. Copy to Overlay makes a whole pack editable, while Revert to plugin restores the supplied version.

Use Export to Overlay to make one of your own packs persistent and available for packaging into a plugin. The Knowledge Builder's AI Assistant can commit entries into packs you published yourself; packs supplied by installed hub plugins remain protected. Its proposal board also survives switching between the proposal and Packs tabs within the same browser tab.

Fateless and Community Stats (Min)​

SkyrimNet has a new home at fateless.ai, bringing together the Plugin Hub and a new way to see what is working well for the community.

See What the Community Is Using​

Ever wondered which models other people use for dialogue, actions, or memory? Or whether a provider is having a rough day for everyone, not just you?

The community stats page lets you explore which models and providers people are using for each variant, compare response speeds and success rates, and see which providers are running smoothly or having trouble. It gives us all a little less guesswork when choosing a setup, and helps us improve the defaults and catch problems earlier. The page is public and available to everyone, whether or not you contribute.

Contributions are anonymous usage and performance statistics, not conversations. No prompts, dialogue, or audio are included, and the statistics are not linked to your Fateless account.

Participation is your choice, under Settings → General → Privacy. Send Anonymous Usage Data is on by default and can be turned off. This setting allows us to gauge how many users we have, roughly what sort of general system specs they have, and to broadcast out notifications (such as new updates, or urgent security issue notifications) to clients. Send Anonymous Usage Metrics, which contributes to the community stats, is off by default and requires the first option. This setting shares things such as the typical TTFT / throughput / response times of the providers you're communicating with (Nothing about what you're actually sending to these providers), and powers the stats page. You can change either setting at any time; neither is required to play, install plugins, or use local smart routing.

The Privacy Policy and What SkyrimNet sends explain this in plain language, including a complete list of the fields each option can send.

Smarter Model and Provider Routing (Min)​

The routing system has been rebuilt to recover from provider failures and slow responses instead of leaving a conversation stalled. All of the local improvements below are available to everyone, with no account or telemetry required.

Local smart routing is enabled by default under AI → Providers. Turning it off restores strict round-robin behavior.

Local Smart Routing​

Failed requests can retry on the next model or provider in your rotation. Timeouts, rate limits, server errors, empty or invalid responses, and connection failures are recognized separately. Repeatedly failing providers are temporarily skipped, then allowed back after a cooldown.

The dashboard gives you more control over those decisions:

  • Provider mixer: inspect available providers, prices, and statistics, and choose the order in which they should be tried.
  • Model rotation: choose sequential or weighted-random selection, set per-slot weights, and reserve backup slots for failover. A weight of zero makes a slot failover-only. Rotations remain overridable per character under AI → Models.
  • Health and planning: see whether a model or upstream provider is healthy, cooling down, or being routed around, including the reason and retry countdown. The Plan tab previews which models the next request would try and why others would be skipped.

An optional quantization floor lets you exclude providers running more heavily compressed versions of a model.

Faster Recovery From Slow Responses (Min)​

A new latency guard detects providers that take too long to start responding and tries another model or upstream provider before waiting out the full timeout. Local routing learns expected response times during normal play; community routing can use the community's observations from the first request.

The original request can stay active while that early retry starts, and SkyrimNet uses whichever starts responding first. This reduces unnecessary silence when the original was only slightly late. Slow providers can also be deprioritized for the session, while the final attempt is allowed to finish rather than abandoning every slow-but-working option.

Fine-tune this under AI → Providers → Routing → First-token guard. Turn early retries on or off, adjust the patience multiplier, set the minimum and cold-start waits, choose whether the original reply can still win the race, and decide whether slow providers move to the back of the order for the session.

Routing notices explain temporary provider avoidance and clear automatically after 45 seconds. The warning that all providers are failing remains until the problem clears.

Community Routing (Min)​

Community routing puts those shared statistics to work. Alongside local smart routing, which learns from your own session, it uses community performance results and provider checks to help SkyrimNet avoid providers that are already having trouble. That means it can make a better first choice rather than waiting for your own request to fail.

Community routing is included with every Patreon and Ko-fi supporter tier. The shared infrastructure behind it costs money to run, and your support helps cover those costs. We are not pay-walling anything - This is an additional hosted service; the mod and all of the local routing improvements remain free for everyone, with no account or telemetry required.

Choose Balanced, Cheapest, or Fastest to guide provider ordering based on reliability, response speed, generation speed, and price. The Activity tab shows the routing updates and decisions.

To use community routing, link your active ko-fi or patreon supporter membership through Fateless and enable both anonymous usage options described above. The statistics remain anonymous and are not linked to your account. Turning either option off, or no longer having an active membership, automatically switches you back to local smart routing without a restart.

Speech, Voice Input, and Audio​

More Reliable Speech Playback (Min)​

The speech pipeline has been rebuilt across NPC dialogue, player speech, Dragonborn Voice Over, Universal Translator, telepathy, thoughts, narration, and bard announcements. It addresses long-standing problems with lines never playing, sentences disappearing mid-response, and audio getting stuck behind stale queue state.

Subtitles now appear when playback actually begins rather than when a line is queued. Vanilla-voice muting follows real playback start and end, and the lipsync driver has been rewritten alongside the rest of the pipeline.

Back-to-back responses from the same actor now execute their associated actions with each line instead of dropping them or handling them out of order. Telepathy and standalone narration no longer make an NPC walk over and face the player; ordinary NPC dialogue and voiced scene lines do so when playback starts.

Sentence Splitting and Subtitle-Only Narration (Min)​

Abbreviations and initials such as Mr. Dragonborn or J. R. no longer split speech at every period. Editable abbreviation tables are included for English, German, Spanish, French, Italian, Polish, Portuguese, and Russian under Settings → Voice → Sentence Splitting.

Voice → Narration → Subtitles only lets you keep descriptive narration on screen without generating narrator audio. Each segment remains visible for approximately as long as it would take to speak. Disabling narration still removes it entirely.

TTS Text Filters (Min)​

Under Audio & Voice → TTS Text Filter, you can remove or replace text before it is spoken while keeping the complete subtitle. This is useful for pronunciation guides, romanization, or bracketed notes that should be visible but not read aloud.

Rules use regular expressions and run in order. An empty replacement removes a match; a nonempty replacement is spoken instead. If filtering removes an entire line, it remains subtitle-only. Invalid patterns are skipped and shown with an error rather than breaking speech.

An optional rule for parenthesized Latin text ships disabled by default. For example, 好 (hǎo) can be voiced as 好 while retaining the pronunciation guide in the subtitle.

OpenAI-Compatible TTS (Elbios)​

A new Voice/TTS → OpenAI-Compatible engine supports Boson.ai Higgs 3 and compatible self-hosted servers, including SkyrimNet audio.cpp deployments, Windows wrappers, and Vast.ai setups.

Choose the Boson.ai service profile or provide your own self-hosted endpoint. The Vast.ai option can create a matching Higgs/Whisper instance. Endpoint testing, health checks, rate-limit handling, and setup guidance are integrated into the dashboard.

Voice cloning enrolls a reference sample once per session and reuses the provider's voice handle. The Transcribe missing reference samples option uses your active speech-recognition provider to recover missing transcripts and caches the result. Uploaded samples retain their transcripts, including samples with non-ASCII filenames, and upload-format guidance is shown on the Voice Samples page.

Voice Input and Playback Fixes (Min)​

  • Local Whisper's first transcription is faster. Warm-up happens while the model loads, adding a little loading time instead of delaying the first thing you say after loading a save.
  • Open Mic handles overlapping input more reliably. It keeps speech that starts while the previous sentence is still transcribing, remains responsive to toggles and voice hotkeys, and continues listening after a voice hotkey is released in a menu. The menu recording itself is discarded.
  • Push-to-talk respects interruption settings. Releasing it no longer discards queued NPC lines when interrupt-on-voice-start is disabled.
  • Silent dialogue placeholders no longer delay generated speech. Actual voiced dialogue still receives the appropriate playback window. Pre-voiced Universal Translator menu replies also register their transformed text correctly instead of being dropped.
  • Player thoughts can begin streaming without waiting for the full response, including replies wrapped entirely in internal-thought tags. With Dragonborn Voice Over, SkyrimNet no longer adds the malformed, underscore-filled subtitle to the player's own dialogue-menu line.

Pocket TTS now defaults to one parallel request rather than two to reduce CPU contention on weaker systems. The setting remains adjustable from 1 to 8.

Gameplay, Memory, and Dashboard Improvements​

Conversations and Actions​

Action confirmations (Min): Custom actions can ask permission before running. Enable Ask the player to confirm before this action runs in the action editor's Advanced settings. Choosing No cancels that action quietly and lets the NPC do something else. This is off by default and configured per action.

Better action targeting (Min): Action selection now identifies nearby actors that are hostile to the player, helping prevent a follower from choosing a friendly target when the requested enemy is not available.

Renamed NPCs (Min): Speaker and target selection can match a plain name to a name extended by a renaming mod, such as Hofgrad the Beggar [Male Nord]. Ambiguous partial matches do not guess between multiple nearby NPCs.

Speech scheduling (Min): GameMaster-directed speech is no longer blocked by the speech-density window, while player-busy and post-interaction cooldowns still apply. Private virtual speakers do not consume the nearby-NPC speech budget and no longer reply to themselves in a loop.

Speaker selection (Oldcustard): The speaker-selection prompt only offers silence when silence is actually a valid choice for that selection.

Carriage awareness (PhospheneOverdrive): Carriage occupants are described as seated in a carriage rather than walking, standing, or occupying a technical marker. Vanilla seats and Convenient Carriages are recognized. The scripted opening cart sequence is not covered.

Memory and Player Input (Min)​

Recalled memories now include relative age, such as Several days ago, Last month, or Over a year ago. Memories from a different season also include that season, giving NPCs clearer context about when something happened.

The chat box now supports combining an NPC target with in-character rewriting. Both @Lydia 'hello and '@Lydia hello rewrite the line and send it to Lydia alone.

Opening the chat overlay can automatically turn Caps Lock off. Reset Caps Lock is enabled by default in chat settings and can be disabled. The telepathy eavesdrop setting now persists between launches.

Dashboard and Diagnostics​

Trigger creation (PhospheneOverdrive): Create Trigger in the Event Log uses the same event-specific condition generation as the Event Monitor. Actor names also resolve correctly from UUIDs on the History Events page.

NPC package settings (Min): Working package controls now live under Conversations → NPC packages. The separate Packages section and its nonfunctional Follow Player and High Priority tables have been removed.

Conversation logs (Min, Dowser): conversation_log.log now includes NPC and player internal thoughts alongside spoken dialogue, including standalone thoughts and inline internal-thought segments. This logging is always enabled, independently of the telepathy setting that filters the Chat UI.

Request and speech diagnostics (Min): System Logs show time to first token alongside total request duration, with generation speed in request details. Provider speed displays use measurements from the current session, falling back to published figures when needed. System → Traces now follows individual spoken lines through synthesis and playback, making slow or missing speech easier to investigate.

Performance and Other Fixes (Min)​

  • Removed an unintended two-second delay from NPC responses, reduced main-thread stalls associated with configuration access, and improved throughput and request prioritization under heavy load.
  • Configuration saves now replace files with complete versions, preventing a crash during saving from leaving a partially written configuration.
  • Fixed a potential crash when Papyrus mods register custom event schemas after a game has loaded.
  • Fixed generated player bios being treated as NPC bios on the Characters page, which could hide Player Settings and the player's voice slots. The memory-recall test dialog also displays memory text, scores, and actor names correctly again.
  • Fixed OmniSight repeating the first worn item's details for other equipment. Provider authentication errors now show the relevant provider's response instead of always claiming an OpenRouter session expired.
  • Reduced repeated warnings from missing optional scene integrations and notifications from custom-prompt calls while global AI is disabled.

The Balanced and Budget presets now use google/gemma-4-26b-a4b-it for vision, replacing the previous rate-limited default.

For Mod and Content Authors​

Packaging and Migration (Min, Zevick)​

Beta25 changes how SkyrimNet discovers and loads content. See the Beta25 migration guide when updating an existing integration.

Under Data/SKSE/Plugins/SkyrimNet/, content is organized as follows:

library/skyrimnet.base/   SkyrimNet's base content
library/{plugin}/        Installed and locally created plugins
external/{plugin}/       Content bundled inside another mod
overlay/                Personal overrides
saves/{id}/              Per-save character bios

Base content has the lowest priority. Library and external plugins share the user-controlled plugin order, with the overlay above them. content-registry.json records order, activation, and per-file settings. Per-save character data is stored separately under saves/{id}/.

Trigger and action filenames must match their name field, case-insensitively. Virtual NPCs are individual entities/<name>_virtual.entity.yaml files; existing definitions migrate from VirtualEntities.yaml into the overlay, with a backup of the old file retained. Knowledge packs derive their author from the plugin that provides them. Older packs containing an author field still import.

Voice effects, naming entries, furniture names, identity links, filters, and Dialogue Actions rules can also be packaged as individual content entries. Furniture-name entries extend and override the built-in aliases rather than replacing the entire list.

Plugin Settings Pages (Min)​

Plugins can now ship their Settings page schema as settings/{Name}.yaml inside the plugin folder, instead of a separate config/plugins/{Name}/manifest.yaml. The schema installs, updates, and uninstalls with the plugin, and changes apply without a restart.

Use the same {Name} as your old config/plugins/ folder. Your scripts continue to use the same Plugin_{Name} configuration, and players keep their saved values.

The legacy path remains supported. If both files exist, the settings/ version takes priority and the log warns about the legacy file. content-convert moves the legacy schema for you. Set min_skyrimnet_version to this release when publishing a plugin using the new path.

Nested defaults such as general.enabled now save in the correct structure rather than as flat keys that read as unset. For an existing settings.yaml affected by that issue, back up the file before removing it to regenerate the defaults. This repair is only for affected files, not a normal upgrade step.

File Editor and Publishing (Zevick, Min)​

Tools → File Editor exposes each content layer as an ordered tree. Unlike the normal editing workflow, it edits the specific copy you select, not whichever version currently wins resolution. Hub and external plugins are read-only; copy them into a new local plugin before editing.

Drag plugins to reorder them, move or copy files with drag-and-drop or Ctrl+C/X/V, and edit plugin metadata from the tree. Relative paths are preserved when files move between plugins. Knowledge packs expand into individually editable entries, with move/copy support between packs even without a save loaded. Active-save bios can be copied into a plugin for reuse across saves. New files target the selected plugin, or the overlay if none is selected. New action definitions still begin in Game Data Explorer.

Package content through Plugins → Package Plugin or the editor toolbar. Create Snapshot freezes a version for publication, while also serving as a backup that can be restored. After signing in and submitting, My Plugins shows the review result, including reasons for rejected submissions.

Plugin metadata supports one or more content languages, required mods, and cover images. Choose languages on the package and publish forms; multilingual plugins appear under each selected language in the hub. Covers must be PNG or JPEG, use a 16:9 aspect ratio, be no larger than 5 MB, and meet the hub's pixel-dimension requirements. Listings can declare their associated mods as well as bundles.

Each published version requires a What changed in this version entry. It supports restricted Markdown without images or links, has a 2,000-character limit, and must be updated when the version changes. This text is shown to users before installation or update and included in the submission's review information.

Developer Kit (Min)​

A separate developer-kit release asset now contains the modding documentation, C++ public API headers, and tools for working outside the game. Documentation and C++ headers are no longer bundled in the normal mod archive.

  • content-convert.exe converts Beta24-and-earlier plugins to the new format. The kit includes a /migrate-beta25 Claude skill to help guide that process.
  • content-validate.exe loads plugins using SkyrimNet's own parsing code and renders prompts with placeholder data. It validates prompts, triggers, actions, and entities without launching the game and uses the same validation approach as the hub. --report out.json writes a report; exit code 0 means clean, 1 means findings, and 2 or higher indicates a tool error.

API, Action, and Audio Behavior​

Actor registration (lemonade8339): C++ PublicAPI functions accepting a FormID register the actor when SkyrimNet has not encountered it yet, instead of failing on an unknown UUID.

Managed packages (Min): The package API supports arbitrary EditorID lookup when adding or removing packages, allowing third-party integrations to use their own packages through SkyrimNet's managed system.

Action eligibility (Min): Eligibility is recalculated each turn in mod-triggered scenes instead of remaining stale after narration or another mod starts the scene. Warnings identify the action, rule index, and decorator, and blank comparison operators are flagged at load time. Actor-less events checked with is_follower produce a warning rather than an error.

Audio events (Min): Existing Papyrus natives and event names remain compatible. SkyrimNet_AudioStarted and SkyrimNet_AudioEnded now include voiced, which is false for subtitle-only segments. Those segments still emit both events in the same order as voiced segments. A line purged before its first segment starts emits neither event.

The old facialAnimation.resolution setting is retired. Existing values are ignored and removed on the next configuration save.

Trigger targets (Min) are available as target_actor, alongside actor and player. target_uuid and originator_uuid are numeric handles suitable for UUID-taking decorators.

notification events (Min) expose corner HUD messages through a message field, including messages from other mods. SkyrimNet's own notifications are excluded.

New and Updated Decorators​

  • available_dialogue (Min) - This decorator exposes the actor's currently available dialogue:
available_dialogue(npc.UUID)              {# Full dialogue tree #}
available_dialogue(npc.UUID, "quest")     {# Quest-progressing branches #}
available_dialogue(npc.UUID, "quest ids") {# Quest branches with script-bearing line IDs #}
available_dialogue(npc.UUID, "fires")     {# Executable endpoints with their form IDs #}

Prefer the filtered modes when a full dialogue tree is unnecessary. Game Data Explorer's actor dialogue tab includes an interactive Conversation Simulator with voice playback for inspecting those choices.

  • get_stage_done(quest, stage) (Min) checks whether a particular quest stage was ever reached, rather than only reporting the current stage. season (Min) exposes winter, spring, summer, or autumn.
  • uses_higgs_native_tags(actorUUID) (Elbios) resolves the actor's effective TTS engine, overrides, and native-tag settings for prompt packages. Native Higgs tags are shared with the legacy Higgs connector.

Request Tracing (Min)​

Request traces include provider, upstream_provider when reported by OpenRouter, and streaming ttft_ms on success and failure paths. Late responses from an abandoned attempt can still contribute timing measurements without being served as the reply. Routing also supports directives scoped to an individual variant, so a provider can be skipped for one task without excluding it from all tasks.
